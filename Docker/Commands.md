#Docker 


## 1. `docker build {java.class} {directory}`
- **Создает образ Docker.**
- `{java.class}` — имя или тег создаваемого образа (например, `my-java-app`).
- `{directory}` — путь к директории, где находится `Dockerfile` (например, `.` для текущей директории).
- **Пример:** `docker build -t my-java-app .`

## 2. `docker run {REPOSITORY or IMAGE ID}`
- **Запускает контейнер из указанного образа.**
- `{REPOSITORY}` — имя образа (например, `my-java-app`).
- `{IMAGE ID}` — идентификатор образа, который можно узнать через `docker images`.
- **Пример:** `docker run my-java-app`

## 3. `docker ps`
- **Показывает список запущенных контейнеров.**
- Вывод включает ID, имя, статус, порты и команду, с которой запущен контейнер.

## 4. `docker ps -a`
- **Показывает список всех контейнеров, включая остановленные.**
- Используется для просмотра завершенных, удаленных или остановленных ранее контейнеров.

## 5. `docker rm {IMAGE or CONTAINER ID}`
- **Удаляет указанный контейнер.**
- `{IMAGE or CONTAINER ID}` — имя или ID контейнера, который нужно удалить.
- **Пример:** `docker rm my-container`

## 6. `docker rmi {REPOSITORY or IMAGE ID}`
- **Удаляет указанный образ.**
- `{REPOSITORY}` — имя образа (например, `my-java-app`).
- `{IMAGE ID}` — идентификатор образа, который можно узнать через `docker images`.
- **Пример:** `docker rmi my-java-app`

## 7. `docker logs {NAMES}`
- **Показывает логи контейнера.**
- `{NAMES}` — имя или идентификатор контейнера (например, `brave_wing`).
- Используется для анализа вывода контейнера (ошибки, действия, сообщения).
- **Пример:** `docker logs brave_wing`
## 8. `docker-compose up`

- **Запускает все сервисы, определенные в файле docker-compose.yml.**
- Используется для запуска приложения с несколькими связанными контейнерами.
- **Дополнительные опции:**
    - `-d`: Запускает сервисы в фоновом режиме (detached mode).
    - `--build`: Пересобирает образы перед запуском.
    - `--force-recreate`: Принудительно перезапускает все сервисы.
- **Пример:** `docker-compose up`

## 9. `docker-compose up -d`

- **Запускает сервисы в фоновом режиме.**
- То же, что и `docker-compose up`, но не блокирует терминал.
- **Пример:** `docker-compose up -d`

## 10. `docker-compose down`

- **Останавливает и удаляет все контейнеры, сети и тома, созданные командой `docker-compose up`.**
- Используется для остановки и очистки окружения.
- **Пример:** `docker-compose down`

## 11. `docker-compose restart`

- **Перезапускает все работающие сервисы.**
- Используется для перезапуска приложения без полной остановки и запуска.
- **Пример:** `docker-compose restart`

## 12. `docker volume create {name}`

- **Создает новый Docker том с указанным именем.**
- Тома используются для сохранения данных, которые должны сохраняться даже после удаления контейнера.
- `{name}` — имя создаваемого тома (например, `my-data`).
- **Пример:** `docker volume create my-data`

## 13. `docker inspect {volume name}`

- **Показывает подробную информацию о указанном томе.**
- Используется для проверки состояния тома, его размера и других параметров.
- `{volume name}` — имя тома (например, `my-data`).
- **Пример:** `docker inspect my-data`

## 14. `docker-compose logs {service name}`

- **Показывает логи указанного сервиса.**
- `{service name}` — имя сервиса (например, `web`).
- Используется для отладки и мониторинга работы сервиса.
- **Пример:** `docker-compose logs web`

## 15. `docker-compose stop`

- **Останавливает все работающие сервисы, но не удаляет их.**
- Используется для временной остановки приложения.
- **Пример:** `docker-compose stop`
